## 모든 라운드에서 지키는 제약 (1·2라운드 계획서에서 옮김)

- 결제·주문·제출 버튼은 처리 중에 `disabled` + `aria-busy="true"` + 진행 표시("주문 중…", "결제 중…")를 가진다. 하단 고정 구매 바의 버튼도 같다.
- PAYING, UNKNOWN은 `--unc` 보라 점선 + "결제 확인 중"으로 확정 전임을 보이고, 취소·재결제 버튼을 두지 않는다.
- AI 검색, 카테고리, 활동 로그가 실패해도 상품 목록·상세·주문 화면의 레이아웃은 정상이다(자리 이동, 빈 화면 없음).
- 남은 수량과 품절은 사실 그대로 보여 주되 카운트다운, 판매율 막대, 깜빡임, "마감 임박" 같은 재촉 표시는 쓰지 않는다.
- 새 라이브러리, 외부 웹폰트, API 필드·서버 변경 없음.
- 같은 의미의 색은 화면마다 같게 쓴다: 주황 = 행동·할인·남은 수량, 빨강 = 오류, 보라 점선 = 확정 전, 회색 = 품절·취소.

## C. 다크 모드 수동 토글 설계 메모

- 선택지는 **자동 / 라이트 / 다크** 세 가지. 자동은 지금처럼 브라우저·OS 설정(`prefers-color-scheme`)을 따른다.
- 라이트나 다크를 고르면 `<html data-theme="...">`를 붙이고, **사이트 설정이 브라우저·OS 설정보다 우선**한다. 지금 CSS가 이미 그렇게 짜여 있다(다크 블록이 `:root:not([data-theme="light"])`라서, 라이트를 고르면 OS가 다크여도 라이트).
- 고른 값은 그 브라우저의 `localStorage`에 저장한다(기기별, 서버 저장 아님). 저장소를 못 쓰면 자동으로 동작한다.
- 첫 화면이 깜빡이지 않게(다크 사용자에게 라이트가 잠깐 보임) `index.html`의 `<head>`에서 React보다 먼저 `data-theme`를 붙인다.
- 버튼 위치는 헤더의 사용자 메뉴 또는 헤더 오른쪽. 구조 요소를 바꾸는 것이므로 위치는 사용자에게 먼저 묻는다(LESSONS B2).
