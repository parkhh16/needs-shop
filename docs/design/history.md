## 1라운드: 디자인 토큰, 홈, 상품 상세, 로그인, 회원가입

**문제**: 접근성 자동 검사(axe)에서 33건이 실패했고 그중 32건이 색 대비였다. 원인은 주황 버튼 위 흰 글자(라이트 3.58:1, 기준 4.5:1)로 추정했고, 구현 뒤 재측정으로 확인됐다.

**한 일**: 색·간격·글자 토큰을 정하고(`tokens.md`) 5개 화면에 적용. designer → frontend-coder → frontend-tester → frontend-reviewer → visual-reviewer 순서.

측정 환경: H2 시드 상품 25개, Vite dev 서버, Playwright 1.63 + axe-core 4.11, 고정 화면 12개 × 모바일(390)/PC(1280) × 라이트/다크 = 48장.

| 항목 | Before | After |
|---|---|---|
| 자동 검사 통과 / 실패 (화면 12개 × 4변형 × 3종 + 흐름) | 122 / 33 | 153 / 2 (3회 반복 동일) |
| axe color-contrast 실패 | 32 | 0 |
| 남은 실패 | - | admin-activity 모바일 라이트/다크 `scrollable-region-focusable` (Before에도 있었음, 릴레이 07에서 해결) |
| 로그인·주문·결제·관리자 흐름 / 콘솔 에러·5xx | 통과 / 0 | 통과 / 0 |
| 결제 버튼 더블클릭 시 결제 요청 수 | 1회 | 1회 (3회 모두) |
| 모바일 390px 가로 스크롤 | 없음 | 없음 |
| 린트 경고 | 26 | 26 |
| 시각 검수 점수 (16장, 10점 만점) | - | 평균 8.7 (최저 상세 8점) |

**리뷰에서 잡아 고친 것**: 같은 검색어에서 AI 검색이 실패한 뒤 성공(0건)해도 "검색에 실패했어요."가 남음(중간), 상세에서 `soldOut=false, stock=0`이면 "0개 남음" 표시(낮음), "결제하기" 처리 중 `aria-busy` 없음(낮음).

**측정 오류를 잡은 것**: 1차 시각 채점에서 홈이 6~7점이었는데, `loading="lazy"` 이미지가 전체 페이지 캡처 때 로드되지 않아 카드가 빈 사각형으로 찍힌 것이었다. 앱이 아니라 캡처 도구 문제라 `e2e/lib.mjs`의 `settle`을 고치고 전후를 모두 다시 찍었다.

## 2라운드: "수량이 정해진 물건을 고르는 갤러리"

**문제** (1라운드 결과 화면을 보고): 첫 화면 400px에 사진이 없고, 카드가 모두 같은 크기라 시선이 머물 곳이 없고, 이 서비스의 핵심 정보(남은 수량)가 가장 작게 보였다. 왼쪽 사이드바가 사진 영역을 줄였고, 로고와 카테고리가 이모지라 환경에 따라 안 보였다. 모바일 상세의 구매 버튼은 약 900px 아래에 있었다.

**방향**

1. 이미지가 주인공인 갤러리. 따뜻한 종이색(라이트) / 먹색(다크) 바탕, UI는 뒤로.
2. 위계는 크기와 굵기 차이로(히어로 제목 28~44px/800, 가격 18~32px/800, 보조 12~13px).
3. 주황은 "행동(구매, 검색)"과 "한정·할인 신호(할인율, 남은 수량 칩)"에만.
4. 모서리를 키우고(카드 이미지 16px, 패널 20px), 그림자는 hover·고정 바·메뉴에서만.
5. 정직한 희소성: 남은 수량은 사실로만, 카운트다운·깜빡임·"마감 임박" 없음.

**바꾼 구조**

| | 1라운드 후 | 2라운드 후 |
|---|---|---|
| 카테고리 | 왼쪽 232px 트리 + 모바일 햄버거 | 가로 카테고리 레일. 사이드바를 지웠다가 PC(1024px 이상)에서는 세로 사이드바를 다시 살림(`a59be17`) |
| 첫 화면 | 검색창 + 예시 칩 + 4열 카드 | 어두운 히어로("정해진 수량만큼만, 좋은 물건을 골랐어요") + 대표 카드 2x2. 이후 상품 배너(`HomeBanner`)가 생겨 배너가 있으면 배너, 없으면 히어로 |
| 남은 수량 | 가격 아래 작은 칩 | 이미지 왼쪽 아래 칩, 품절은 이미지 전체 스크림 + "품절" |
| 상세 구매 | 본문 사이 구매 정보, 구매 제한이 세 곳에 | 구매 패널 한 덩어리, 모바일 하단 고정 구매 바 |
| 로고·아이콘 | `⚡` 이모지 | 인라인 SVG (외부 라이브러리 없음) |

**사용자 판단을 요청한 것**: 사이드바 제거, 히어로 문구와 어두운 면, "남은 수량이 적은 상품" 레일(재고를 크게 드러내는 것이 경쟁 구매를 부추기는지), 홈 대표 카드, 다크를 차가운 회색에서 따뜻한 먹색으로. 이 중 사이드바는 판단을 기다리는 중에 먼저 지워져서 "사이드바 없애버린겨?"라는 질문이 나왔고, 구조 요소는 먼저 묻는다는 규칙이 생겼다(LESSONS B2). 그 뒤 PC에서는 사이드바를 되살렸다.

**로고**: 후보 4종(배너 톤 3종 포함) → 2차(모노클·안경) → 3차(작은 크기용 모노클 3종과 안경 비교)를 거쳐 둥근 안경 마크로 정했다(`frontend/src/logo.ts`). 비교판 이미지는 지웠다(커밋 `2024079`, `087a6c7`, `ed79c74`).

**결과 수치는 남기지 못했다.** 2라운드는 화면 구조를 바꾼 라운드라 전후 스크린샷([r2-after](shots/r2-after/))만 있다. 1라운드처럼 같은 지표로 잰 표가 없다는 점이 이 라운드의 아쉬운 점이다.

## 관리자 도움말 (#17)

관리자 화면의 소개 문단을 한 줄 요약 + "?"로 나누고, 브라우저 기본 `title` 호버 설명을 `HelpTip`(호버·포커스·탭)으로 바꾸고, 메뉴·표 글자를 키웠다. build 통과, lint 24, e2e 220/0. 표 글자를 키우면서 상품 재고 입력칸의 "-출고" 안내가 잘리는 회귀를 1건 발견해 입력칸 폭을 110 → 128px로 고쳤다. 전후: [relay-admin-help](shots/relay-admin-help/).
