# 후기·인기·핫딜 표시: 돈과 재고를 건드리지 않고 "잘 팔리는 쇼핑몰"처럼 보이게 하기

## 문제

상품 목록이 가격과 재고만 보여 주어 어떤 상품을 먼저 볼지 판단할 근거가 없었습니다. 후기(별점), 인기·핫딜 표시, 품절 상품 뒤로 보내기를 넣어야 했는데, 이 프로젝트의 핵심은 재고와 돈이 어긋나지 않는 것이라 **표시를 위한 기능이 주문·결제 경로를 건드리면 안 됩니다.** 처음 떠올린 "재고가 적으면 자동으로 가격을 내린다"는 방식이 특히 위험했습니다.

## 원인(고려한 것)

- **재고 연동 자동 할인**: 재고가 줄 때마다 가격이 바뀌면 상품 화면의 가격과 주문 시점의 가격이 어긋나고, 결제 금액·대사·정합성 리포트의 기준이 흔들립니다. 재고 차감을 한 문장 UPDATE로 하는 원칙에도 가격 변경이 끼어듭니다. 경제적으로도 재고가 적다는 것은 수요가 높다는 뜻이라 값을 내릴 이유가 없습니다.
- **후기 수집**: 이 데모에는 실제 구매자가 없어 후기는 샘플 데이터일 수밖에 없습니다. 표본이 부자연스러우면(전부 4.8점) 오히려 가짜로 보입니다.
- **인기 표시**: 누적 판매량(`sold_count`)은 오래된 인기를 계속 보여 줍니다. "지금 인기"는 최근 판매량이어야 합니다.

## 해결

1. **가격은 바꾸지 않고 표시만 한다.** 할인은 관리자가 정한 값(`originalPrice`)만 쓰고, 핫딜 배지는 "할인 중이고 재고 1~10개"일 때 표시만 붙입니다(`ProductResponse.from`). 가격·재고·주문 코드는 수정하지 않았습니다.
2. **인기 배지는 최근 7일 PAID 수량을 읽어 만든다.** 주문 상품과 주문을 조인한 읽기 전용 집계 한 번으로 수량 상위 3개(5개 이상)를 구하고, 서버 메모리에 30초 캐시합니다. 서버가 2대면 배지가 최대 30초 어긋날 수 있지만 표시용 파생 값이라 재고·결제에는 영향이 없어 전파하지 않았습니다. 집계가 실패하면 배지 없이 응답합니다(부가 기능이 핵심 흐름을 막지 않는다).
3. **후기는 읽기 전용 샘플 데이터다.** `product_review` 테이블과 `product.review_count`/`rating_sum`(목록에서 상품마다 후기를 세는 N+1을 피하기 위한 비정규화)을 Flyway V10으로 추가했습니다. 후기 작성 기능은 없으며, 화면의 후기 구역에 "데모용 샘플 데이터"라고 밝힙니다.
4. **샘플 후기는 결정적으로 만든다.** 상품 이름 해시로 고정한 난수로 만들어 같은 결과가 나오고(테스트로 확인), 현실적인 모양을 따릅니다: 1점이 2·3점보다 많은 J자형, 상품 평균은 모두 4.1 이상(대부분 4.1~4.7), 후기 0개 상품 3개, 후기 수는 0~60개, 본문 없는 별점만 남긴 후기 20%, 상품 스펙을 언급하는 문장.
5. **품절은 맨 뒤로.** 모든 정렬에서 `CASE WHEN stock <= 0 THEN 1 ELSE 0 END`를 첫 정렬 키로 둡니다. 숨기지는 않습니다(링크와 재입고 시 노출 유지).
6. **인기 배지용 데모 판매는 정상 주문 경로(결제 시작, 승인, 재고 차감)로 만들고 생성 시각만 최근으로 옮깁니다.** 정합성 리포트가 시드 후에도 0건임을 테스트로 확인합니다. 운영 프로필(`prod`)은 데모 회원이 없어 이 시드가 실행되지 않습니다.

| 상품 상세 | 후기 없음 | 평균·별점 분포(5→1점)·후기 목록(10개씩 페이지 번호) |

| 재고·가격 코드 변경 | - | 0줄 (표시 계층만) |
